### Decision points

- D1 — Child test shape. Parametrize the existing
  `test_claude_child_hook_cannot_change_parent_lifecycle` over both host
  kinds (renamed `test_child_hook_cannot_change_parent_lifecycle`) instead
  of copying it. Recommended: one test, one rule.
- D2 — Claude wake recognition. Options: (a) wait for the capture and match
  the exact wrapper text; (b) for Claude, treat any prompt that contains a
  complete bus wake notice as a wake when recording the turn.
  Recommended: (b). It is correct whether or not a wrapper is present, needs
  no captured text in source, and is fail-safe: a false positive only marks
  the turn as not owner-started, so a decision answer is refused and the
  owner answers again. It never permits an action. Codex keeps the exact
  match (its `codex queue` prompt is the bare notice, and
  `test_prompt_hook_marks_a_bus_wake_turn` protects "quoting is an owner
  turn" for Codex); D5 proposes removing this difference. The
  acknowledged-wake no-op stays exact-match only, because there a false
  positive would tell the agent to ignore a prompt. The capture (Task 3)
  remains required as evidence and for the docs; it only changes code if
  the notice text does not arrive verbatim (then stop, see Task 3).
- D3 — Non-owner turns. Recommended: document only. The hook payload has no
  origin field; `/loop` prompts are owner-authored text, and recognising
  background-report or peer-message wrappers would key security behaviour
  on undocumented host strings. The known-limits text already says turn
  checks stop mistakes, not a deliberate agent.

  the checkout. Owner decision (2026-11-13): record them as GitHub issues in

  the deltas below override the Codex exact-match text elsewhere in this
