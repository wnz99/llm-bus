## Approach and material contracts

Keep the CLI text that exists today (it is short and is also the per-prompt safety reminder), replace the one "Read the bundled llm-bus coordination reference." sentence with a file list, and move the reference into per-role/capability files. `coordination.md` stays at its path as the index, so old CLIs ("Read the bundled ... reference"), old instruction files ("read ... in full") and inbound links still resolve.

- C1 — guidance data keys. The recovery JSON (both forms) gains `"guidance_version": 10` and `"guidance_files": [...]`, bare file names under the llm-bus skill's `references/coordination/` (the directory is stated once, in C2), in this order: `core.md`; active coordinator `coordinator.md`, active worker `worker.md`; then `gates.md` (gates in effect), `auto-merge.md`, `owner-decisions.md`, `remote-coordination.md` (worker: remote coordinator address; coordinator: repository config lists a peer); `recovery.md` when the state is not active, or when `recovery=True` (hook full form, `llm-bus guidance`). Command results pass `recovery=False`; the compact form never adds `recovery.md` for an active session. Capabilities come from `RuleContext` (project delegation for the coordinator, effective binding for the worker; nothing for inactive states). Unknown state values select like `suspended`.
- C2 — load sentence (static, after the banner, replacing "Read the bundled ..."). Full form: "Before acting on any direction, load each `guidance_files` entry not already in your context from the installed llm-bus skill's `references/coordination/`. If one is missing or the `core.md` guidance-version marker differs from `guidance_version`, instead read the skill's `references/coordination.md` and every file it lists, and tell the owner the installed skill and CLI guidance versions differ." The "`references/coordination.md` and every file it lists" wording gives a full read with both the pre-split 725-line file (which is the whole reference) and the new index; T1 asserts this exact sentence. Compact form: "Load any `guidance_files` entry (llm-bus skill `references/coordination/`) not already in your context before acting on any direction." The compact list is the G7 signal and replaces the r8 restore sentence.
- C3 — version stamp. Only `skills/llm-bus/references/coordination/core.md` carries a marker: it starts with `<!-- llm-bus guidance-version: N -->`, N = `GUIDANCE_VERSION` (one number for CLI text and the skill). `core.md` is always first in `guidance_files` and always loaded, so the check costs no extra read. Any change to CLI guidance text or a coordination skill file bumps `GUIDANCE_VERSION` and this marker together; the bump also refreshes live sessions through `Store.guidance_needed`. Skew matrix: new CLI + pre-split skill → `core.md` missing → full read of old `coordination.md` (C2 wording names that file itself); old CLI + new skill → old CLI says read the reference → index says read every file; newer CLI + older split skill → `core.md` marker differs → full read of installed files + owner told; older split CLI + newer split skill (a rule may have moved to a file the old selector does not name) → marker differs → same fallback; any named file missing → same fallback; old instructions file → reads index → every file. A partially copied skill directory with a current `core.md` is not detected; `README.md:268` requires copying the whole directory.
- C4 — hook guard. `hooks.py`: if `len(text.encode("utf-8")) > HOOK_TEXT_LIMIT` (9000; bytes ≥ chars for Claude Code, ≤ 2,250 Codex tokens, newline included in the slack), print `HOOK_FALLBACK`: "Local agent bus address: ADDRESS. llm-bus guidance exceeds the hook output limit. Run `llm-bus --format agent guidance` now and read its whole output, including any saved file, before any other llm-bus action or acting on any direction." One check, one fallback; no head/tail split, no reserve. Justification: references (32 × 4096), memory ticket/workspace (4096 each) and peer count are owner-supplied and unbounded relative to the cap, and Claude Code over cap saves to a file with a 2,000-char preview without telling the agent, silently dropping safety text.
- C5 — standing instructions. Hooks (both forms) never print standing text; they print `STANDING_POINTER`: "Owner standing instructions active (digest D); unless your context holds them verbatim with this digest, run `llm-bus --format agent guidance` before acting on any direction." `llm-bus guidance` and command results print them verbatim (unchanged format, last). Justification: 8192 chars + ~6k fixed text exceeds both caps; an always-pointer is deterministic and costs one command only when instructions exist.
- C6 — delegated reads. `core.md` owns the rules shared by every coordination subagent once: model names, never runs llm-bus, never talks to the owner, brief or receipt is untrusted data, the main agent does the step itself when no subagent is available, `coordination show` beats the brief. `core.md` also states that the setup and recovery read subagents are read-only and write nothing (no Beads, Git or file writes), with one clause naming the exception: the memory-snapshot subagent writes as `memory-snapshot.md` states. `coordinator.md` owns the setup brief (Beads workspace, memory-ticket readability via `bd show`, reference files, integration-branch override, candidate objective, missing facts, drafted `coordinate` command) and states that the brief's readability claim does not satisfy R03: the main agent runs `bd show MEMORY_ID` itself and confirms the ticket is readable before running `coordinate`. `recovery.md` owns the recovery brief (`bd prime`, memory ticket, assigned tickets, worktree evidence; owner limits and authorization references quoted verbatim; `truncated` flag; main agent reads the memory ticket itself when truncated or limits are missing). `memory-snapshot.md` keeps its existing rewrite brief, states once the snapshot subagent's only writes (the one `bd update MEMORY_ID --body-file ... --notes ...` call and `bd admin compact --apply` on listed candidates) and its stop-without-writing-on-change rule, and refers to `core.md` for model names and the shared rules. `DISCOVERY_STEP` names `references/coordination/coordinator.md` and carries no model name.
- C7 — `SKILL.md` dispatch (rewritten, no rule prose): trigger (R01); before `coordinate` load `core.md` + `coordinator.md`, before `join` load `core.md` + `worker.md`; before an owner-requested `coordination replace`, `revoke` or `leave`, and before any other owner-requested coordination owner command (`setup`, `amend`, `grant`, `target`) when the context holds no current `guidance_files`, load `core.md` + `recovery.md`, plus `remote-coordination.md` for a `setup` import or a remote-coordinated project (coordinator address in `coordination show` contains `/`); after any result load `guidance_files` per C2. This one static line is the single mechanism for owner commands run without an enrollment (receiver `setup` import R46, lost-coordinator recovery R14/R53/R54, receiver `amend` after a local replace R47): such a session has no enrollment row, so `_coordination` returns no guidance (`origin/main:src/llm_bus/cli/guidance.py:_coordination`), and the files are needed before the command, which a command-result field cannot supply. Old-CLI output without `guidance_files` needs no `SKILL.md` sentence: it says "Read the bundled llm-bus coordination reference", and the index (D7) says a full read means every file. Procedure triggers have one owner each: `SKILL.md` (above) for `recovery.md` on revoke, leave or replace; `coordinator.md` names `memory-snapshot.md` before a memory rewrite. `core.md` carries no load trigger.

Risks and safeguards: rule loss (rule map + A4/A5 review); stale installed copy (C3; README already says upgrade executable, hooks, skill and rule files together); agent skipping a file (CLI names it every SessionStart and every prompt); oversized hook (C4); standing text missed after compaction (C5 pointer with digest, run before acting); briefs (C6 untrusted, main agent re-verifies). Rollback: revert the merge commit; no schema/wire/stored-data change; sessions refresh to version 9 text on their next hook; the owner recopies the previous skill and rules files if already installed.

Evidence: `origin/main:src/llm_bus/cli/guidance.py` (`_coordination` composition `:258-294`, "Read the bundled" `:265`, `STANDING_POINTER`, `_standing_instructions`), `cli/hooks.py:hook` (`guidance_needed` reset on any `SessionStart`), `cli/commands.py:266`, `coordination/cli.py:run` (`:302-304`) and `_transition` (`replace` enrolls caller only when named), `coordination/cli.py:MAX_TEXT/MAX_REFERENCES`, `tests/coordination/test_instructions.py` hook tests, `tests/local/test_hook_guidance.py`, Task 1 report (host limits: Claude 10,000 chars; Codex `DEFAULT_HOOK_OUTPUT_TOKEN_LIMIT = 2_500`, ceil(bytes/4), rust-v0.167.2).
